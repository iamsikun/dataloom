# Running the experiments

Dataloom contains ten experiment families. Each has a small smoke configuration
and a full configuration specifying the experiment grid, estimators, seeds, and
replication counts. Smoke runs validate execution; they do not establish the
paper's numerical results. For saved camera-ready values and their provenance,
use the [replication archive](replication.md).

## Environment

From the repository root, with Python 3.13 and uv installed:

```sh
uv sync --frozen --group dev
uv run --frozen pytest -q
```

The project uses NumPy, SciPy, pandas, PyArrow, joblib, Matplotlib, and PyYAML.
`uv.lock` pins the environment. All experiments use CPUs. The `dev` group also
provides Jupyter for inspecting the historical notebook.

## Experiment map

Configuration names below are relative to `configs/`. Replace `_smoke.yaml` with
`_full.yaml` for the corresponding full profile. Seeds are fixed in each YAML.

| Family | Purpose | Smoke configuration | Data | Seed root |
| --- | --- | --- | --- | --- |
| 1 | Allocation phase diagram, scaling, and oracle comparisons | `exp1_smoke.yaml` | Gaussian simulation | 20260502 |
| 2 | Adaptive allocation and safety diagnostics | `exp2_smoke.yaml` | Gaussian simulation | 20260502 |
| 3 | Multichannel allocation | `exp3_smoke.yaml` | Multichannel simulation | 20260502 |
| 4 | Interval coverage and bias adjustment | `exp4_smoke.yaml` | Gaussian simulation | 20260502 |
| A | Tabular synthetic augmentation | `expA_smoke.yaml` | UCI Adult | 20260502 |
| B | Causal estimation with known potential outcomes | `expB_smoke.yaml` | IHDP-style synthetic population | 20260502 |
| R1 | Equality boundary and zero-variance comparisons | `expR1_boundary_smoke.yaml` | Gaussian simulation | 20260727 |
| R2 | Remainder and non-power-law sensitivity | `expR2_remainder_smoke.yaml` | Deterministic risk curves | 20260727 |
| R3 | Hierarchical external-pilot diagnostics | `expR3_hierarchical_smoke.yaml` | Gaussian simulation | 20260727 |
| R4 | Auxiliary-covariate pseudo-labeling | `expR4_adult_auxiliary_smoke.yaml` | UCI Adult | 20260727 |

R3 and R4 distinguish external-pilot and diagnostic rows from final evaluation
rows. Experiment B constructs a fixed synthetic population with its own
`population_seed`; it does not download the canonical IHDP data.

## Run and analyze a profile

```sh
RUN_DIR=$(uv run --frozen python scripts/run_experiment.py --config configs/expR1_boundary_smoke.yaml)
uv run --frozen python scripts/analyze_run.py "$RUN_DIR"
```

The runner prints the exact result directory on stdout and sends logging to
stderr. Pass that directory to the analyzer. Do not choose a run by its modification
time when reproducing a specific result.

A run directory has the form `results/<experiment>__<commit>__<UTC timestamp>`;
a `__dirty` suffix records uncommitted files. It contains:

- `config.yaml`: the configuration actually used.
- `env.json`: Python/package versions, Git revision, and local execution metadata.
- `raw/`: partitioned Parquet files with per-method results and diagnostics.
- `aggregated/`: analysis tables, generated by `analyze_run.py`.
- `figures/`: PDF and PNG plots, generated by analysis.
- `logs/`: reserved log directory; capture stderr if you need a complete console log.

R4 additionally records the Adult cache schema, row count, and SHA-256 in
`adult_source.json`. Generated result directories are ignored by Git. Environment
records from new runs can contain hostnames and working-directory paths; the
published archive's records have been sanitized.

## Prepare Adult data

Before running A or R4:

```sh
uv run --frozen python scripts/prepare_adult.py
```

This reuses a validated cache or downloads the public Adult training table,
drops rows with missing values, adds binary income and sex indicators, and checks
for the genuine schema and **30,162 cleaned rows**. The cache is
`~/.cache/dataloom/adult.parquet`. Download failures stop preparation. No source
rows are redistributed in this repository or the release.

```sh
# Check an existing cache without accessing the network.
uv run --frozen python scripts/prepare_adult.py --check-only
```

If an older installation cached a synthetic stand-in, move that file aside before
rerunning preparation. The legacy `load_adult()` library function can still create
a stand-in after a failed download for compatibility. The documented preparation
and smoke workflows reject it. Run the strict check before invoking A directly;
R4 also validates the genuine schema in its runner.

The source is [Adult, Becker and Kohavi](https://doi.org/10.24432/C5XW20), licensed
under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Downloading the data
does not change its license to the MIT license used for this project's code.

## Smoke suite and CPU settings

```sh
uv run --frozen python scripts/prepare_adult.py
bash scripts/run_remaining_smokes.sh
```

Despite its historical filename, this helper runs and analyzes **all ten** smoke
profiles. It checks all supplied profiles before starting, requires a valid Adult
cache when A or R4 is included, and stops at the first command failure. It does
not run full profiles. To select particular smoke profiles:

```sh
bash scripts/run_remaining_smokes.sh configs/expR1_boundary_smoke.yaml configs/expR2_remainder_smoke.yaml
```

The original smoke/full YAMLs remain unchanged. For constrained machines, copy a
configuration and change `parallel.n_jobs`: `1` runs sequentially, a positive
integer limits workers, and `-1` uses all available cores. Keep the seeds and
statistical grid unchanged when comparing equivalent runs. `output.results_root`
can point to another directory. The runner saves the modified config with the run.
Some targeted R experiments execute sequential loops regardless of this setting.

Full profiles can be substantially more expensive than smoke checks, especially
R3. Runtime depends on the CPU and worker count; no fixed runtime is promised.
Use [the release archive](replication.md) to verify retained results without
rerunning full simulations.

## Interpreting outputs

Inspect `failure_flag`, `failure_reason`, fallback rates, and finite replication
counts alongside MSE or coverage. A safe fallback to real-only is an observed
behavior, not evidence of an efficiency gain. Some historical product-surrogate
comparators have missing estimates; the archive records their finite-estimate
aggregation and diagnostics. Preserve these limitations when summarizing results.

The historical [full-run summary](../results/full_run_summary.md) records both
successful and unfavorable findings. Estimator identifiers, including
`old_fixed_share_*`, are compatibility identifiers used in saved data. Their
presence does not endorse a fixed calibration share as the optimal rule.

The [saved notebook](../notebooks/exp_analysis.ipynb) requires original raw inputs
that are no longer all available and selects runs by modification time, including
smoke runs. Its saved outputs are retained as a historical record. The notebook
generator overwrites those outputs; use the pinned archive's figure builders for
the camera-ready paper.
